# Froggi marketing

Froggi sells to people who document real work — a carer after a shower round, a property manager at a flat handover, a caretaker in a boiler room with no signal. The material you write should sound like it understands that work, and every claim in it must hold when a customer tries the product the next day. Those two things matter more than polish.

## Before writing

Read what you need from `references/`, not everything:

| File | Read it when |
|---|---|
| `references/product.md` | always — what Froggi does, and **what status each feature has** |
| `references/audiences.md` | the piece targets a sector, or you need examples and pains |
| `references/pricing.md` | the piece mentions plans, prices, the trial or upgrading |
| `references/brand.md` | the piece has a visual side (flyer, slide, social image, layout) |

Then settle four things, from the request or by a sensible default — ask only if a wrong guess would waste the whole piece:

1. **Format and length** — a LinkedIn post is not a flyer is not a landing section.
2. **Audience** — one of the four sectors, or "all" for general pieces. A piece aimed at everyone persuades no one; when in doubt pick the sector the request hints at.
3. **Language** — German (Swiss) unless asked otherwise. French, Italian and English are the product's other languages.
4. **Goal / call to action** — usually "Demo anfragen", "30 Tage kostenlos testen", or contact `hello@froggi.ch`.

## Claims: only what is true today

`references/product.md` marks every feature **live**, **coming** or **planned**. This is the most important rule of the skill, because an overpromise in a care home's procurement file is remembered:

- **live** — say it plainly.
- **coming** — only with a clear marker ("demnächst", "in Kürze"), never in a headline or a comparison table.
- **planned** — leave it out unless the piece is explicitly about the roadmap.

Do not invent customer names, quotes, numbers of customers, certifications, awards, time savings in percent, or hosting locations. If a piece wants proof the facts don't give, write a placeholder like `[Kundenzitat]` or `[Zahl einsetzen]` and say so after the piece, rather than making something up.

## Voice

The website sets the voice; match it.

- **Concrete over abstract.** Name the object and the action: "Wohnungsübergabe mit Fotos und Zählerständen", not "effiziente Prozesse". Use the sector's own words (see audiences).
- **Short, confident, calm.** Short sentences, one idea each. No exclamation marks in running text, no superlatives ("revolutionär", "der beste"), no buzzwords ("KI-gestützt", "disruptiv", "Game-Changer", "nahtlos").
- **Benefit first, feature second.** "Sehen, was fällig ist" before "Erinnerungen nach Wochenplan".
- **Sie-form**, Swiss orthography: `ss` never `ß`, CHF with apostrophe thousands (`CHF 1'990`), dates `10. Oktober 2026`.
- **Taglines that exist:** "Dokumentieren, was zählt. Sehen, was fällig ist." (hero) and "Mach den Sprung." (the frog logo's idea, used for contact/CTA). Reuse them; don't coin a new slogan each time unless asked.
- **The product is called Froggi** — never "FROGGI", "Froggi App" in running text, or "die Froggi". "Froggi" takes no article.

## Formats

Keep these shapes unless the request says otherwise.

- **LinkedIn / social post** — a first line that stands alone (it's all people see), 3–6 short paragraphs or a short list, one CTA, 0–3 hashtags at the end. Under ~1'200 characters.
- **Website section** — eyebrow (1–2 words), title (≤ 8 words), lead (1–2 sentences), then 3 points or a short paragraph. Match the existing sections' rhythm.
- **Newsletter / feature announcement** — what changed, for whom, how to use it (one step), when it's available, plan if gated.
- **Flyer / one-pager** — headline, 3 benefit blocks, a "So funktioniert's" line (Objekt › Aktion › Details), plans teaser, CTA with contact. Fits one A4 side.
- **Cold e-mail** — ≤ 120 words, one sector-specific pain, one sentence on Froggi, one ask (15-minute demo). No attachments promised.
- **Ad copy** — headline ≤ 30 characters, description ≤ 90; give 3 variants.
- **App store text** — subtitle ≤ 30 characters, promotional text ≤ 170, description in short paragraphs; only features the **app** has (see product.md).

## Delivering

Give the piece ready to paste. After it, add a short note (2–4 lines) listing anything the reader must check: placeholders you left, claims marked "coming", prices that depend on the pricing branch going live. If you offer variants, make them genuinely different (angle, not just wording) and say which you'd pick.
